Privacy Risk

top-k index 本身也是隐私暴露面

已有工作表明，仅利用 top-k indices 也可能进行 label inference attack；因此 Clover 同时隐藏 value 和 index。

Why Not Direct SecAgg?

为什么不能直接套普通安全聚合？

方案 A：展开成密集向量

Sparse: A = (2,+0.8), (7,-1.1)
Dense: [0,+0.8,0,0,0,0,-1.1,0,...]

优点：可以直接用密集 SecAgg。
问题：通信回到 d 维，稀疏化优势消失。

方案 B：所有客户端使用同一组 index

Shared index set: {2,7}
A: use {2,7}
B/C: forced to use {2,7}

优点：位置对齐，聚合容易。
问题：不是每个客户端自己的 top-k，可能损害模型效用。

Clover 要保留标准 top-k：每个客户端自己选 index，同时隐藏 index/value 并完成聚合。

Clover Problem
能否在隐藏 value 和 index 的同时，正确聚合多个客户端的 top-k 稀疏梯度？

Core Difficulty

隐藏单个更新，仍要完成聚合

服务器不能看到某个客户端具体选了哪些位置、每个位置的值是多少，但最后仍然要得到所有客户端更新的聚合结果。

Individual updates

Client A: (2,+0.8), (7,-1.1)
Client B: (3,-0.5), (7,+0.6)
Client C: (1,+1.2), (5,-0.4)

->

Aggregated result

G[1]=+1.2
G[2]=+0.8
G[3]=-0.5
G[5]=-0.4
G[7]=-0.5

Reveal the aggregate, hide each individual update.

Distributed Trust

用三个服务器分散信任

客户端不把明文 top-k 更新交给单个服务器，而是将更新拆分/编码后发给三个服务器。

Client top-k update
(index, value)
Server 1share
Server 2share
Server 3share
三个服务器协作计算聚合结果；单个服务器看不到完整的 index/value。
核心思想：分散“看见单个更新”的能力，保留“计算总和”的能力。

SparVecAgg

SparVecAgg：用“重排 + 秘密洗牌”还原稀疏向量

1. 重排 sparse vector

x = [0,+0.8,0,0,0,0,-1.1,0]
x' = [+0.8,-1.1,0,0,0,0,0,0]

客户端把非零值移动到向量前面，后面补 0。

2. index 编码进 permutation

x = permutation(x')

原来的位置不再作为明文 index 上传，而是由 permutation 表达。

3. secret-shared shuffle

shares(value) + shares(permutation)
-> dense vector shares

服务器在秘密分享域里执行洗牌，恢复位置并聚合。

Clover 不对每个 (index, value) 做 ORAM 写入；它把 index 隐藏进 permutation，再用 secret-shared shuffle 恢复位置。

原理四

安全聚合之外，还需要 DP

安全聚合保护单轮单客户端更新，差分隐私限制最终模型泄露训练数据。

  • 二者解决的问题不同，不是互相替代。
  • Clover 采用分布式噪声生成，避免单点完全信任。
  • 隐私预算越强，噪声越大，效用可能下降。

实验

性能和效用之间的系统折中

论文的重点不是超过无保护 FL，而是在隐私保护下尽量保留可用性。

  • 相比通用分布式 ORAM 基线，服务器侧通信和运行时间提升数个数量级。
  • 客户端通信成本更低。
  • 模型效用接近 vanilla FL with central DP。
通信

客户端上传量保持稀疏化收益。

时间

专用聚合比通用 ORAM 基线更快。

效用

接近带中心化 DP 的普通联邦学习。

讨论

安全系统总有部署代价

Clover 的设计完整，但也带来信任、复杂度和适配范围上的限制。

  • 三服务器非合谋假设在真实部署中需要组织保障。
  • 协议和系统实现比普通 FL 更复杂。
  • 目前主要围绕 top-k，大模型微调仍需进一步验证。

信任假设

三个服务器需要相互独立，不能完全合谋。

系统复杂度

安全聚合、DP 噪声和完整性检查都增加实现成本。

适配范围

其他压缩方式和超大模型训练还需要更多研究。

总结

Clover 把稀疏化、安全聚合和差分隐私放进同一个系统权衡里

它保留 top-k 带来的通信优势，同时隐藏稀疏梯度的位置和值，并通过分布式 DP 限制最终模型泄露风险。
