# Mac 基准实验补充结果

## 说明

这组数据用于给原报告补充一份 macOS 下的基准实验结果，只做四项基础测试：

- 顺序读 `read`
- 顺序写 `write`
- 随机读 `randread`
- 随机写 `randwrite`

本次 Mac 补充实验沿用了和原报告尽量一致的参数：

- `ioengine=pvsync`
- `bs=4k`
- `numjobs=1`
- `iodepth=1`
- 通过普通文件进行测试，不直接访问裸设备

这次 Mac 补充实验已经按和 Linux 基准一致的文件大小执行，即测试文件使用 `5g`。因此在测试参数层面，这组数据和 Linux 主实验保持一致；不过两边的硬件、操作系统和文件系统不同，所以结论仍然更适合用于“平台差异补充”，不适合简单地把两组数字直接当成设备优劣排序。

## 测试环境

- 操作系统：macOS 12.3.1
- 机器型号：MacBook Pro (MacBookPro15,1)
- CPU：6-Core Intel Core i7 2.2 GHz
- 内存：16 GB
- 存储设备：APPLE SSD AP0256M 251 GB
- 文件系统环境：APFS
- `fio` 版本：`fio-3.39`

系统原始信息保存在：

- `mac_baseline_results/system_info.txt`

| 测试类型 | IOPS (k) | 带宽 BW (MB/s) | 延迟 Latency (ms) |

Linux 基准值取自当前报告正文中的基础性能表：

| 测试类型 | Linux IOPS (k) | Linux BW (MB/s) | Linux Latency (ms) | Mac IOPS (k) | Mac BW (MB/s) | Mac Latency (ms) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 顺序读 | 454.0 | 1859.0 | 1.51 | 166.5 | 682.0 | 0.0055 |
| 顺序写 | 467.0 | 1915.0 | 1.72 | 100.6 | 412.2 | 0.0093 |

## 结果解读

1. 顺序读和顺序写都明显低于 Linux 报告中的 NVMe 主实验。顺序读约为 `682.0 MB/s`，顺序写约为 `412.2 MB/s`，说明这台 2018 款 MacBook Pro 的 SSD 在 `4k + 单线程 + pvsync + APFS` 这组条件下，整体吞吐不如 Linux 主实验中的 Samsung 980 PRO。

2. 随机读在 Mac 上仍然高于 Linux 主实验，达到 `28.6k IOPS / 117.1 MB/s`。这说明在 macOS/APFS 这条路径上，即使文件大小已经扩大到 `5g`，随机读仍然比 Linux 那组更积极地受益于缓存、预读和文件系统实现细节，因此这一项不能简单解释成“Mac 硬件随机读绝对更强”。

3. 随机写是这组补充实验里最明显的差异点。Mac 上的随机写只有 `2.7k IOPS / 11.1 MB/s`，平均延迟约 `0.368 ms`，而 Linux 主实验的随机写是 `379k IOPS / 1553 MB/s`。这说明在 `pvsync + 普通文件 + APFS` 的组合下，随机小块写入的代价非常高，文件系统元数据更新、回写策略和底层设备处理路径都可能放大这类负载的开销。

4. Mac 这组延迟虽然整体仍低于 Linux 表中的数值，但已经不像 1G 测试那样全部压到极小的微秒级。特别是随机写延迟上升到了 `0.3678 ms`，这也说明在 5G 文件条件下，缓存对结果的“美化”比小文件测试弱了很多。

5. 如果后面想把这组 Mac 数据写进报告正文，建议把它放成“补充对比实验”，不要直接替换原来的 Linux 基准表。更稳妥的写法是：

   - Linux 主实验：作为正式基准
   - Mac 补充实验：作为不同操作系统和文件系统环境下的对照现象

## 建议写法

如果要在报告里补一句简短分析，可以直接写成下面这种风格：

> 在 macOS 12.3.1 的补充实验中，采用与 Linux 基准一致的 `5g + 4k + pvsync + numjobs=1 + iodepth=1` 参数后，顺序读约为 682.0 MB/s，顺序写约为 412.2 MB/s，随机读约为 117.1 MB/s，而随机写仅约为 11.1 MB/s。与 Linux 主实验相比，Mac 平台在随机写场景下表现出更明显的性能下降；同时，随机读仍高于 Linux 结果，说明文件系统和缓存策略对文件级测试结果有显著影响。因此，这组实验更适合作为不同系统环境下的补充对照，而不是单纯的硬件优劣比较。
