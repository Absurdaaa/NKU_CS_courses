## 3. 实现两个版本的算法

这是本次作业里最重要的技术安排。不要只写最优解，建议同时保留一个朴素解法，用来支持复杂度说明和性能对比。

### TODO

- [x] 实现朴素版本 `max_sliding_window_bruteforce`
- [x] 实现优化版本 `max_sliding_window`
- [x] 两个版本返回结果保持一致
- [x] 主接口默认调用优化版本

### 推荐设计

- `validate_inputs(nums, k)`：参数检查
- `max_sliding_window_bruteforce(nums, k)`：暴力解法，便于对照
- `max_sliding_window_deque(nums, k)`：单调队列解法
- `max_sliding_window(nums, k)`：对外统一接口

### 为什么这么设计

- 符合课程里“模块化设计、分解、抽象”的要求
- 便于在报告里解释 SRP
- 便于后面做 profile 对比
- 后续如果扩展“滑动窗口最小值/平均值”等功能，也更容易说明 OCP

### 复杂度预期

- 暴力解法：时间复杂度 `O(nk)`，空间复杂度 `O(1)` 或 `O(n-k+1)`（不含输出时为 `O(1)`）
- 单调队列解法：时间复杂度 `O(n)`，空间复杂度 `O(k)`

### 产出物

- `src/sliding_window.py`

### 检查标准

- 正确性先于优化
- 两个版本对同一输入结果一致
- 代码结构清楚，不把校验、算法、命令行逻辑揉在一起
