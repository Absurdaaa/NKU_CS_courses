    \begin{abstract}
    随着游戏开发、智慧城市、虚拟现实等领域的快速发展，高质量三维场景的自动化生成需求日益增长。程序化内容生成（Procedural Content Generation, PCG）技术通过算法规则驱动场景构建，能够高效产生大规模三维内容，但传统方法依赖专家手工编码，门槛高、灵活性差。近年来，大语言模型（Large Language Model, LLM）在自然语言理解和代码生成方面展现出的强大能力，为 PCG 技术的智能化升级提供了新的可能。本报告选取 SceneX（AAAI 2024）与 UnrealLLM（ACL 2025 Findings）两篇代表性论文进行深入调研，从论文内容、创新点、优势、不足、可实现性和性能指标六个维度展开详细分析，并对两篇论文的技术路线进行横向对比与综合评价。

        \noindent
        \textbf{关键字：大语言模型，程序化内容生成，三维场景生成，多代理框架，Blender，Unreal Engine 5}
    \end{abstract}

%====================一、引言====================
\section{引言}
\label{sec:intro}

三维场景建模是游戏开发、智慧城市、虚拟现实、影视制作等众多应用领域的基础性工作。传统的人工建模方式成本高昂且效率低下，难以满足大规模场景的快速迭代需求。程序化内容生成（PCG）技术作为应对这一挑战的重要手段，通过预先定义的算法规则和参数化模板，能够以少量代码驱动生成大量多样化的三维内容，在场景构建的速度和规模上展现出显著优势。

然而，传统的 PCG 方法面临若干固有局限。首先，PCG 规则的编写需要深入的专业知识，普通用户难以参与场景定制过程。其次，预定义的生成规则缺乏语义理解能力，难以根据自然语言指令灵活调整输出。再者，随着场景规模的扩大，手工编码的规则库难以管理，场景要素之间的空间关系和语义一致性难以保障。

大语言模型的出现为上述挑战提供了新的解决思路。LLM 在自然语言理解、代码生成和推理规划方面展现出的能力，使其有望成为连接人类意图与程序化规则之间的桥梁。根据技术路线的不同，现有的 LLM+PCG 研究大致可分为两个方向：一类以 Blender 等三维创作软件为平台，利用 LLM 驱动程序化资产生成；另一类以 Unreal Engine、Unity 等专业游戏引擎为平台，利用 LLM 连接更底层的 PCG 系统，实现高可控性和交互性的场景生成。

本报告选取的两篇论文恰好分别代表上述两个方向。SceneX 由中科院自动化所等机构提出，以 Blender 为平台，构建了 PCGHub 资源平台与 PCGPlanner 规划器，实现了大规模三维场景的程序化生成。UnrealLLM 由香港科技大学（广州）等机构提出，以 Unreal Engine 5 为平台，通过五代理协作框架将自然语言与专业 PCG 系统深度连接，首次实现了可交互的三维场景生成。

\section{论文一：SceneX}
\label{sec:scenex}

SceneX 全称为"SceneX: Procedural Controllable Large-scale Scene Generation"，由中科院自动化所、中科院大学、国科大北京、地大北京、山大及港科大广州等机构联合提出，发表于 AAAI 2024（Proceedings of the AAAI Conference on Artificial Intelligence, Vol. 39, No. 10, pp. 11826-11834）。

\subsection{论文内容简介}

SceneX 的核心目标是将大语言模型的语义理解能力与 Blender 平台上的程序化内容生成能力相结合，使普通用户仅需通过自然语言描述即可驱动大规模三维场景的自动化构建。在 SceneX 之前，Infinigen、CityDreamer 等程序化生成系统已经能够基于规则和随机种子生成地形、建筑、植被等场景要素，但这些系统存在三个共性问题：程序化模块的多样性受限于预定义规则集，扩展新能力需要大量手工编码；规则编写依赖专业知识，非技术背景的设计师难以参与场景定制过程；复杂场景中各要素之间的空间关系和语义一致性难以通过手工规则有效管理。

SceneX 的系统由两大核心组件构成：PCGHub 资源平台和 PCGPlanner 规划器。PCGHub 整合了 172 个程序化生成资产（覆盖地形、天气、植被、建筑等 14 类能力）和 11,284 个三维静态模型，并提供数千份手工编写的 API 文档，作为 PCG 控制器的标准协议平台。PCGPlanner 负责根据用户指令生成可执行的 Blender Python 操作序列，引导程序化模块完成可控、精确的三维资产生成。

PCGPlanner 采用四阶段自动化流水线架构。第一阶段为场景分解（Scene Decomposition），大语言模型根据系统化提示模板解析用户意图，将自然语言描述转化为场景图表示，图中节点代表场景对象，边代表空间和语义关系。第二阶段为地形生成（Terrain Generation），LLM 调用 PCGHub 中的地形生成 API，构建基础地形并应用相应材质。第三阶段为对象生成与检索（Objects Generation \& Retrieval），对于程序化可生成的资产直接调用生成 API，对于需要从资产库选取的静态模型则使用 CLIP 编码器进行文本-图像检索。第四阶段为资产放置（Assets Placement），LLM 选择布局类型、定义空间关系、超参数生成器推导量化参数，最终由程序化布局生成器调用 Blender API 完成资产排列。

该框架能够根据文本描述自动生成森林、山脉、海岸线、无界城市等多种场景类型，同时支持场景编辑功能，如资产放置、季节转换等。

\subsection{创新点}

SceneX 的主要创新点体现在以下四个方面。

\textbf{PCGHub 资源整合平台。} 该平台汇集了 172 个程序化资产，覆盖地形（12 个）、天气（15 个）、植被（65 个）、建筑（37 个）、区块（17 个）、城市（12 个）、人物（6 个）以及水体、雪景、资产放置、材质、动态人物、动态植被、动态车辆等 14 类生成能力。同时收录了 11,284 个高质量三维静态模型。这一整合方案有效解决了传统 PCG 方法中资产多样性受限的问题，为场景生成提供了丰富的资源支撑。

\textbf{系统化提示模板。} 研究者设计了结构化提示模板 $P_i(R_i, T_i, D_i, F_i, E_i)$，其中 $R_i$ 定义智能体角色（如"你是一位 Blender 程序化建模专家"）、$T_i$ 描述任务目标与约束、$D_i$ 从 PCGHub 中检索相关 API 文档作为上下文知识注入、$F_i$ 指定输出格式（如 JSON 或 Python 代码）、$E_i$ 提供少量输入-输出对作为少样本示范。该模板借鉴了 Chain-of-Thought 推理思想，通过结构化引导降低 LLM 在复杂规划任务中的推理偏差，显著提升了执行成功率。

\textbf{三层放置决策机制。} 在资产放置阶段，SceneX 由 LLM 驱动的三层决策机制处理复杂的空间关系推理：第一层由 LLM 根据场景语义从五种预定义布局类型中选择最合适的方案；第二层由 LLM 定义资产间的空间关系；第三层由超参数生成器将空间关系转化为密度、间距、朝向等量化参数。这种将语义决策与数值计算分离的设计提高了布局推理的可靠性。

\textbf{五类程序化布局生成器。} 研究者提出了散点布局（Scatter）、网格布局（Grid）、线性布局（Linear）、嵌套布局（Nested）和区域填充布局（Area Filling）五种布局生成器，能够模拟现实世界中多样化的空间排列模式，覆盖了从自然植被到城市建筑的各种场景排列需求。

\subsection{优势}

SceneX 的主要优势包括以下几个方面。

\textbf{高效性。} 得益于 PCGHub 和 PCGPlanner 的协作，SceneX 能够在数小时内生成大规模高质量三维资产（包括地形、城市、森林等），而同等规模的场景若由专业人员手工建模则需要两周以上的时间。

\textbf{可控性。} SceneX 支持根据自然语言描述进行场景编辑，用户可以通过文本指令添加对象、在特定位置放置对象、进行季节转换等操作，满足个性化的场景定制需求。

\textbf{多样性。} 通过整合和协调多个子任务，SceneX 在大规模场景生成上达到了较高的灵活性与多样性，能够覆盖自然场景和城市景观两大类场景类型。

\textbf{低门槛。} 该框架降低了非编程人员的使用门槛，普通用户无需掌握 Blender 的复杂操作，仅通过自然语言指令即可生成复杂的三维场景。

\textbf{开放性。} PCGHub 采用模块化设计，新增的程序化资产和 API 文档可以持续纳入平台，便于社区贡献和生态扩展。Blender 作为开源软件也保证了平台的可获取性。

\subsection{不足}

SceneX 的主要不足体现在以下四个方面。

\textbf{平台依赖性。} SceneX 依赖 Blender 平台，其程序化能力受限于 Blender 内置的 PCG 工具集。Blender 的渲染管线和视觉效果（如全局光照、体积渲染）与 Unreal Engine 5 等专业游戏引擎存在代际差距，限制了生成结果的视觉保真度。

\textbf{资产检索局限。} 虽然整合了 11,284 个三维静态模型，但 CLIP 编码方案基于图像视觉特征设计，对于地形生成参数这类缺乏直观视觉表现的程序化参数，其语义匹配精度存在不足。特别是对于需要精确几何参数的资产类型，检索效果受限。

\textbf{缺乏直接交互能力。} SceneX 主要面向静态三维资产生成，对生成场景的游戏交互、物理仿真等动态特性支持有限。用户只能查看生成结果，无法在场景中行走、探索或与场景对象进行物理交互。

\textbf{参数推断的歧义性。} 当用户描述中缺少必要的参数信息时，超参数生成器需要自动推断合理参数，这一过程可能引入不确定性，导致生成结果与用户预期出现偏差。

\subsection{可实现性}

SceneX 的可实现性总体较高。首先，Blender 提供了开放的 Python API 接口，支持通过脚本调用几乎所有内置功能，PCGHub 对 Blender API 的封装规范且完整，可直接通过自然语言驱动生成调用。其次，CLIP 预训练模型已在大量数据上训练完成，文本-图像检索方案成熟可用，无需额外训练。再者，系统化提示模板的设计基于成熟的 prompt engineering 方法，无需额外的模型训练或微调。此外，PCGHub 的资源平台采用模块化设计，便于持续扩展和社区贡献。整体而言，SceneX 的技术栈建立在已有的成熟方法之上，不依赖额外的模型训练，具有较高的可复现性。

\subsection{性能指标}

SceneX 在多个维度上进行了实验验证。在生成质量评估中，SceneX 的平均得分（AS）达到 7.83，专业人员平均得分（AES）达到 7.70，两项指标均显著优于 Magic3D、DreamFusion、Text2Room、CityDreamer、Infinigen、3D-GPT 等六个基线方法。在 CLIP 相似度评估中，使用 ViT-L/14、ViT-B/16 和 ViT-B/32 三种编码器进行衡量，SceneX 在所有基于 Blender 或 PCG 的基线方法中表现最优。SceneX 未公布其 ER@1 和 SR@1 指标。

\section{论文二：UnrealLLM}
\label{sec:unrealllm}

UnrealLLM 全称为"UnrealLLM: Towards Highly Controllable and Interactable 3D Scene Generation by LLM-powered Procedural Content Generation"，由香港科技大学（广州）、XGRIDS 和哈尔滨工业大学（深圳）联合提出，发表于 ACL 2025 Findings（pp. 19417-19435）。

\subsection{论文内容简介}

UnrealLLM 针对高质量三维场景自动化创建中如何保留程序化内容生成优势这一核心挑战，创新性地将自然语言描述与专业 PCG 系统（Unreal Engine 5）相连接，实现了场景生成的全面自动化。与 SceneX 等基于 Blender 的方案相比，UnrealLLM 在渲染质量（通过 Nanite、Lumen 实现）和物理仿真（通过 Chaos 实现）方面具有显著优势，更重要的是首次实现了可交互的三维场景生成。

UnrealLLM 的核心贡献在于构建了一个五代理协作框架。场景分析智能体（Scene Analyst）负责接收用户的自然语言描述并分解为结构化子任务。资产管理智能体（Asset Manager）从多模态资产库（MegaScan + Objaverse）中检索适合当前场景的三维资产。节点专家智能体（Node Expert）内置 PCG 知识库（含约 100 个 UE5 PCG 节点定义），通过 RAG 技术按需检索节点知识。模式专家智能体（Pattern Expert）负责空间模式和环境模式知识，并参与 Spline 几何控制的生成。蓝图生成智能体（Blueprint Generator）整合前四个智能体的输出，采用基于 JSON 的领域特定语言（DSL）生成可执行的 UE5 PCG 蓝图代码。

UnrealLLM 还引入了基于 Spline 的几何控制增强机制，用户可以通过自然语言生成边界样条线、路径样条线和分布样条线，实现对场景布局的精确几何控制。此外，系统利用 UE5 的 Chaos 物理引擎支持角色行走、游泳、物体破坏等游戏交互行为，使用户能够以第一人称视角在生成的世界中自由探索。

\subsection{创新点}

UnrealLLM 的主要创新点体现在以下五个方面。

\textbf{文本化 PCG 蓝图表示。} 研究者提出了基于 JSON 的领域特定语言（DSL），将 UE5 原生的节点级 PCG 图结构以文本格式表示。这一设计解决了 LLM 与图形化编程环境之间的表示鸿沟，使 LLM 能够理解和生成 UE5 的蓝图代码。JSON DSL 精确描述了每个节点的类型、输入参数和连接关系，通过解析器可还原为 UE5 可直接执行的蓝图图结构。

\textbf{多代理 PCG 自动化框架。} 五代理协作框架将复杂的 PCG 专业知识分解到专门化的智能体中，通过协同问题解决实现可靠的场景生成。各智能体之间通过结构化的消息传递协议进行通信，允许并行处理和独立优化，提高了系统的可扩展性和容错能力。

\textbf{基于 RAG 的知识库检索。} 节点专家智能体内置包含约 100 个 UE5 PCG 节点定义的 PCG 知识库，通过 RAG 技术根据具体任务动态检索最相关的节点知识。这种按需知识供给的方式避免了将全部专业知识一次性塞入 LLM 上下文窗口的效率损失，提高了节点选取的准确性。

\textbf{多模态资产检索。} 资产库基于 MegaScan 免费资产和 Objaverse 数据集构建，每个资产具有文本描述、图像特征和几何特征三种表示。检索采用多模态相似度融合策略：
$$S(A,q) = \lambda_t \cos(E_q, E_t(A)) + \lambda_v \cos(E_q, E_v(A))$$
综合文本嵌入与视觉嵌入的余弦相似度来评估资产与用户描述之间的匹配程度，在几何特征的捕捉上优于单纯的 CLIP 图像检索。

\textbf{Spline 几何控制增强。} 利用自然语言自动生成控制样条线，通过边界样条线（定义场景边界轮廓）、路径样条线（定义道路、河流等线性轨迹）和分布样条线（控制沿轨迹的资产密度分布）实现对复杂场景布局的直观几何控制，突破了纯文本描述在空间精度上的限制。

\textbf{可交互场景生成。} 首个支持与生成场景直接进行游戏交互的系统，基于 UE5 的 Chaos 物理引擎和内置游戏系统实现角色行走、游泳、物体破坏等动态交互行为，使生成结果不仅是静态模型，更是可运行的虚拟世界。

\subsection{优势}

UnrealLLM 的主要优势包括以下几个方面。

\textbf{高渲染质量。} 基于 Unreal Engine 5 平台，充分利用 Nanite 虚拟几何体系统和 Lumen 动态全局光照技术，能够生成照片级渲染质量的三维场景，视觉效果显著优于 Blender 等三维创作软件。

\textbf{高可控性。} 五代理框架实现了从自然语言到 UE5 蓝图代码的端到端映射，支持多种艺术风格（照片级、写实风、低多边形等），同时 Spline 几何控制机制提供了精确的空间约束能力。

\textbf{强交互性。} 首次实现了自然语言驱动的可交互三维场景生成，用户可以在生成的世界中行走、游泳、与物体发生物理交互，突破了传统场景生成工具仅输出静态模型的局限。

\textbf{高可靠性。} 多代理框架中各智能体分工明确，通过知识库和 RAG 技术确保 PCG 任务执行的可靠性。完整系统 ER@1 达到 75.6\%，表明系统在大多数情况下能够一次性生成正确的蓝图。

\textbf{大规模生成能力。} 支持无界规模的三维场景生成，利用 UE5 的流式加载和 LOD 技术满足大型开放世界的需求。

\textbf{蓝图生成模型的关键发现。} 实验发现 o1-mini 作为蓝图生成智能体时取得最佳效果（ER@1 达 83.0\%），揭示了在程序化蓝图生成这类需要精确推理的任务中，模型的推理能力比参数量更为关键。

\subsection{不足}

UnrealLLM 的主要不足体现在以下五个方面。

\textbf{知识库质量依赖性。} 系统性能高度依赖 PCG 知识库的质量和覆盖范围。知识库中若存在不完整或错误的节点定义，将直接影响生成结果的可靠性。随着 UE5 版本更新，知识库需要持续维护和扩展。

\textbf{资产库的覆盖局限。} 尽管基于 MegaScan 和 Objaverse 构建了多模态资产库，但面对多样化需求时仍存在覆盖盲区，特别是在特定文化风格或细分场景类型上。

\textbf{复杂交互模式的局限。} 实现复杂、多步骤的交互模式可能需要手动调整，系统在自动化生成与完全自定义之间存在权衡。

\textbf{计算开销。} 多代理架构涉及五个并行的 LLM 调用和 RAG 检索，计算密集，可能影响资源受限环境中的实时性能，增加系统延迟。

\textbf{外部依赖。} 系统需要访问 MegaScan 和 Objaverse 等外部数据源，在网络受限或数据源不可用时可能受到影响。此外，UE5 作为商业软件存在授权成本。

\subsection{可实现性}

UnrealLLM 的可实现性中等偏高。UE5 提供了原生的 PCG 系统和开放蓝图接口，文本蓝图 DSL 的设计与转换方案清晰可行，多模态表示可借助现有 MLLM 与 CLIP 模型实现自动化标注。五代理框架的通信协议和协作流程有清晰的定义。然而，该系统在系统工程复杂度上显著高于 SceneX，需要构建和维护专业的 PCG 知识库、设计代理间的通信协议、实现 JSON DSL 的解析器以及与 UE5 PCG 系统的对接，开发团队需要同时具备 LLM 应用开发和游戏引擎使用的技术储备。

\subsection{性能指标}

UnrealLLM 在执行成功率方面进行了系统性的消融实验。完整五代理系统达到 ER@1（首次精确匹配率）75.6\% 和 SR@1（首次成功率）73.2\%。当采用 o1-mini 作为蓝图生成智能体时，ER@1 提升至 83.0\%，表明推理能力强的模型在程序化蓝图生成任务上优势明显。在美学质量评估中，UnrealLLM 的 GPT 美学评分为 7.71。在 CLIP 相似度方面，使用 ViT-L/14 编码器测得的分数为 26.34，高于 SceneX 的 22.82。

%====================五、总结与展望====================
\section{总结与展望}
\label{sec:conclusion}

本报告对 SceneX（AAAI 2024）和 UnrealLLM（ACL 2025 Findings）两篇论文进行了全面调研与技术分析。两者代表了大语言模型与程序化内容生成技术深度融合的两种典型范式：SceneX 以 Blender 为平台，侧重程序化资产生成的自动化，以简洁的流水线架构降低了技术门槛；UnrealLLM 以 Unreal Engine 5 为平台，侧重交互与精细控制，以多代理协作框架实现了专业级场景生成能力。

综合分析表明，当前 LLM+PCG 技术仍面临若干共性挑战：资产库的覆盖率和多样性有待提升；生成结果的可控性与用户意图的对齐程度需要提高；多代理协作的可靠性尚未达到理想水平（约四分之一的首败率）；计算开销问题在资源受限环境中尤为突出。未来研究方向可包括：探索更大规模的程序化资产生态；研究更精确的文本-空间映射方法；优化多代理架构的通信效率和推理并行度；将物理仿真约束更好地融入生成过程；以及拓展多模态交互能力。
