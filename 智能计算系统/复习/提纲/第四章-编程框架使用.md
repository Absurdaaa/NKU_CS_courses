## 一、编程框架概述(P4–P8)
- **为什么需要框架**:深度学习算法多层结构、含大量共性运算(卷积/池化/激活),把这些操作封装成组件 → 提升算法开发效率;封装后硬件程序员也能针对硬件做专门优化,充分发挥硬件效率。P4–6
- **定义**:把深度学习基本操作封装成一系列组件,这一系列组件即构成一套深度学习框架。P7
- **主流框架**(易考名词):PyTorch(Facebook/Meta,2017)、TensorFlow(Google,2015)、Keras(Google,2015)、Caffe(BVLC,2013)、PaddlePaddle(百度,2018)、MindSpore(华为,2019)。P8

## 二、PyTorch 概述(P11–P16)
- **起源 Torch**:IDIAP 2002 发布,LuaJIT 接口、C/C++ 内核。**PyTorch = Py + Torch**,2017 Facebook AI Research 开源,基于 Torch 的 Python 机器学习库,具备强大的 GPU 加速张量计算能力(类似 NumPy)。P11–12
- **设计原则**:基于 Python、把研究人员放首位、易用、高性能、内部实现简单。P13
- **发展历程关键点**:0.2 版(2017.8)支持高阶导数、分布式、**张量广播**;0.4 版张量与变量合并;1.0 版 PyTorch Hub;2.0 版(2023.3)增加**编译模式**。P15

## 三、NumPy 基础(P18–P30)
- **ndarray(array)**:NumPy 最重要的数组类,面向高维数组的批量化处理。P18
- **创建方法**:`np.array`、`np.arange(start,stop,step)`、`np.zeros/ones/full/eye/empty`、`np.random.random`。P19–22
- ◆**one-hot 编码**:`np.eye(num_class)[label_array]` 对标签做 one-hot。例 `np.eye(3)[[0,1,0,2]]`。P23
- **属性**:`ndim`(维度)、`shape`(各维尺寸)、`size`(元素总数=shape 各元素乘积)、`dtype`(默认 float64)、`itemsize`。P24–25
- **形状操作**:`reshape`(元素数/数据不变)、`np.resize`(不足则循环复制补充)、`a.resize`(不足补0)。P26–27
- **局限性**(⭐对比 tensor 的关键):**原生 NumPy 只能在 CPU 上运行**;为在 GPU 上跑出现了 CuPy/Numba/PyCUDA/PyTorch。P30

## 四、张量 Tensor(P31–P52)
### ⭐ Tensor 与普通(CPU)矩阵的区别 P31, P30, P33
- **张量定义**:计算图上的数据载体,在节点间传递/流动的数据;可看作 n 维数组,**维数=阶数**(0=标量,1=向量,2=矩阵,n=n维数组)。P31
- ⭐**与 NumPy ndarray(普通矩阵)的核心区别**:**张量可运行在 GPU 或深度学习处理器上,性能更高**;而原生 NumPy 矩阵只能在 CPU 上。张量还支持**自动求导**(requires_grad)、参与**计算图**。**张量更适合深度学习运算**(如在通道维度聚合卷积等多维批量运算)。P31, P30
- ⭐**二者互相转化**:`torch.from_numpy(ndarray)` 从 NumPy 生成 tensor;`tensor.numpy()` 从 tensor 转 NumPy。**注意:from_numpy/numpy 产生的二者共享内存**,改一个另一个也变。GPU 张量转 NumPy 须先 `.cpu()` 再 `.numpy()`。P33, P42
- **创建 tensor**:直接 `torch.tensor([...],requires_grad=True)`;`torch.ones/zeros/rand(3,2)`;按已有张量 `rand_like/zeros_like/ones_like`;`cat/concat`(连接)、`stack`(新维连接)、`split`(切分)、`take`。P32, P34

### 张量属性
- **常用属性**:`dtype`(数据类型)、`shape`(各阶长度)、`device`(所在设备)、`grad`(backward 后的梯度,默认 None)。P35
- **dtype**:`torch.float32/float16/float64`、`int8/16/32/64`、`bool`、`bfloat16`。例 `torch.zeros([2,2],dtype=torch.int8)`。P36
- **数据位宽**(理解即可):深度学习有"大间距"容忍非精确计算,**训练不需全 float32**(神经元/权值 8bit、梯度 8-16bit 可精度无损)。FP8 E4M3 适合权重/激活(前向),FP8 E5M2 适合梯度(反向)。P37–40
- **device**:`'cuda:n'` 第 n 个 GPU,`'dlp:n'` 第 n 个深度学习处理器。P41
- **转换 `tensor.to()`**:转数据类型或设备类型。转 DLP 两种方式:`a.dlp()` 或 `a.to(torch.device('dlp'))`。P42, P44
- **形状转换 `reshape(*shape)`**:某维可写 -1,自动推算。P43
- **复制 `tensor.clone()`**:返回完全相同张量,存于新内存,**仍留在计算图中**。P45

### ⭐ 张量数据格式(data layout)P46–47
- **NCHW vs NHWC**:代表多维数组以何种线性方式存储。**PyTorch、GPU 用 NCHW**;**TensorFlow、CPU 用 NHWC**。N=batch、C=通道、H=高、W=宽。一张 RGB 图 N=1,C=3。
- **NCHW**:按 W→H→C→N 存,同通道像素连续,适合对**每个通道单独运算**(如 maxpooling)。**NHWC**:按 C→W→H→N 存,不同通道同一位置连续,适合**跨通道同像素运算**(如 Conv1x1)。P47

### 索引、切片、维度变换
- **索引/切片**:基本同 NumPy;切片 `[start:end:step]`(含 start 不含 end);start 可负,**step 不能为负**。P48–50
- **维度压缩/扩展**:`torch.squeeze(input)` 移除所有尺寸为1的维;`torch.squeeze(input,dim)` 仅移除指定维(若该维为1);`torch.unsqueeze(input,dim)` 在 dim 处插入尺寸1的维。P51
- **自动求导**:`requires_grad`(默认 False)控制是否求导;**操作的输入中只要有一个需求导,输出就需求导**。P52

## 五、操作 operation(P53–P62)
- **定义**:接收若干张量输入,更新原张量或生成新张量输出;是模型训练/推理的基础。P53
- **三种写法**:`torch.add(a,100)` / `a.add(100)` / `a.add_(100)`。P54
- ⭐**原位(in-place)操作**:标志是操作后加 `_`(如 `add_`),在原内存上直接更新,**节省内存**(推理时有用)。但会覆盖原张量:训练时用原位更新梯度会破坏训练;多张量引用同一张量时原位操作会互相影响。P55–56

### ⭐◆ 广播机制 broadcasting(必考计算题)P57–61
- **作用**:维度不匹配的多个张量,自动把不匹配维度扩展到相同维度后再运算。P57
- ⭐◆**能否广播的判断规则**(三选一才能在某维对齐):①两张量都至少有 1 维;②**从末尾维开始对齐**比较,该维满足下列之一才合法——(1)**尺寸相同**;(2)尺寸不同但**其中一个为 1**;(3)**其中一个张量没有该维**(视为补 1)。任一对齐维不满足 → **报错(不可广播)**。P57
  - 例:`ones(2,3)` 与 `ones(2,2)` → 末维 3≠2 且都不为1 → **不可广播(报错)**。P58
  - 例:`ones(2,3,3)` 与 `(2,3,1)` → 末维 3 vs 1 → **可广播**,结果 `(2,3,3)`。P58–59
  - 例:`ones(2,3,3)` 与 `(3,1)` → 缺的最高维补 1 得 `(1,3,1)`,逐维 1↔2、3↔3、1↔3 → **可广播**,结果 `(2,3,3)`。P58, P60
- ◆**手算扩维步骤**:①维数不同时,**从末尾对齐,前面缺的维补 1**;②对每个为 1 的维,把它沿该维**复制扩展**为另一张量的尺寸;③扩展后两张量同形,再逐元素运算。P59–60
  - 典型考法"一维 vs 维度3":如 `(3,1)` 与 `(2,3,3)` → `(3,1)` 先补成 `(1,3,1)` → 行方向(尺寸3那维)保持、列方向由1扩到3、最高维由1扩到2 → 得 `(2,3,3)`。P60
- ⭐**原位操作的广播限制**:若**需要扩展/改变的是执行原位操作的那个张量本身 → 编译报错**(如 `ones(2,3,1).add_(ones(2,3,3))` 报错);若需扩展的是**作为参数**的张量则仍可广播(如 `ones(2,3,3).add_(ones(2,1,1))` 可以)。P61
- **常用计算操作**:`add/subtract/multiply/divide`、`bitwise_*`、`sin/cos/tanh`、`where(cond,x,y)`、`sort`、`round/ceil/floor`、`transpose`、`to`。P62

## 六、⭐ 计算图 computational graph(P63–P67)
- ⭐**概念**:框架用**有向图**描述计算过程,由**节点**和**边**组成,可用 C++/Python 构建;**计算图对应神经网络的结构**。示例 `y=w*x`。P63
- ⭐**节点**:表示各类操作(数学运算、变量读写、数据填充),也可表示输入数据、模型参数、输出。**边**:节点间输入输出关系,两类——①传递数据的边(传的就是 tensor);②**控制依赖边**(不传数据,只规定执行顺序:前序算完后序才开始)。P64
- ⭐**静态图 vs 动态图**(点名考点):
  - **静态图**:先定义整张图再运行。优点——可**全局优化、运算更快**;缺点——**调试不方便**。P65
  - **动态图**:即时运行,模型可在运行时修改。优点——**编写灵活、可立即拿到结果、调试方便**;缺点——**优化不方便**。P65
  - **执行差异**:静态图先构图、每次 iteration 重复执行同一张图;动态图**每次 iteration 都构建并执行新图**,反向传播结束后整个计算图即在内存中被释放。P66
- ⭐**典型框架支持**:**TensorFlow 1.x 是静态图,PyTorch 是动态图**;现在 PyTorch/TensorFlow/PaddlePaddle/MindSpore 都同时支持静态图与动态图,Caffe2 只支持静态图。P66–67

## 七、模型推理实现:整体流程(P69)
读取输入图像 → 构建神经网络 → 实例化 → 调试 → 模型优化。P69

### 1. 读取与显示图像 P70–81
- **PIL**:`Image.open()`,读入格式 `(W,H,C)`;`mode/size/save/convert/resize`。P70–71
- **PIL↔张量**:用 `torchvision.transforms`;`Compose` 组合多步;`ToTensor` 把 `(H,W,C)`、[0,255] 转为 `(C,H,W)`、float、[0.0,1.0];`ToPILImage` 反向。P72–75
- **OpenCV**:`cv2.imread` 读入 numpy.ndarray、uint8、0-255,**BGR 格式**(需 `cvtColor` 转 RGB)。P76–77
- **torchvision.io**:`read_image` 返回 `(C,H,W)`、uint8 张量。P78
- **matplotlib.pyplot**:`imshow/title/plot/figure/show/ion/ioff/pause` 绘图显示。P80–81

### 2. 构建神经网络 P82–97
- **两条路**:自定义模型(`torch.nn`/`nn.Module`/`nn.functional`)或调用预训练模型(`torchvision.models`)。P82
- **`torch.nn.Module`**:模型基类,自定义需继承;含 `__init__`(初始化模型结构/参数)与 `forward`(定义前向计算)。**因支持自动求导,forward 中无需写反向**。P83–84
- **parameter 与 buffer**:parameter 可学习(反向时被优化器更新)、保存在 `state_dict`;buffer 不可学习(分 persistent / non-persistent,前者进 `state_dict`)。保存模型保存的是 `state_dict`(parameter+persistent buffer)。P85
- **常用方法**:`parameters()/buffers()/state_dict()`、`register_parameter/register_buffer`、`requires_grad_()`(冻结部分模块精调)、`zero_grad()`、`train()/eval()`。P86–87
- **创建 parameter**:①成员变量用 `nn.Parameter(...)`(自动注册);②`nn.Parameter` 后 `register_parameter()`。buffer 用 `register_buffer()`。P88–90
- ⭐**nn vs nn.functional**:`torch.nn.xx` 是**类**,在 `__init__` 实例化、可含可学习参数;`torch.nn.functional.xx` 是**函数**,在 `forward` 中调用,参数需自己在 `__init__` 创建初始化。以 Conv2d 为例对比。P91–95
- **`nn.Sequential`**:序列容器,按顺序封装一串操作,可切片索引构建子模块。P96–97

### 3. 调用预训练模型 P98–104
- **迁移/精调(fine-tune)**:在初始任务上训好,再在目标任务上微调,省时省算力。P98
- **`torchvision.models`**:大量预训练模型;`models.vgg19(weights=...)` 加载结构+权重。P99
- **应用**:用 `weights.transforms()` 做输入预处理;vgg 含 `features/avgpool/classifier` 三段。P100–101
- ⭐**`model.train()` vs `model.eval()`**:差别在 **BN 和 Dropout**。`eval()` **不启用 Dropout、BN 用训练得到的 running_mean/var**(推理前必须调用)。P102–103

### 4. 实例化、调试、优化 P105–131
- **实例化步骤**:定义 module → 初始化参数 → 实例化(传结构参数)→ 定义输入 → `model(img)` 取输出。P105, P118
- **参数初始化**:`torch.nn.init`(`zeros_/ones_/constant_/uniform_/normal_/xavier_*/kaiming_*` 等)、`Module.apply(fn)`、`self.modules()` 循环。P106–117
  - **Xavier**:满足 Glorot 条件(各层激活值/梯度方差一致),适合 tanh 等关于0对称的激活。P109–111
  - **Kaiming**:针对 ReLU/PReLU 非对称激活,CV 任务常用。P112–113
- **调试**:pdb;`print(model)`;`torchsummary.summary`;**TensorBoard**(`SummaryWriter`,`add_scalar/histogram/image/graph` 等)。P119–123
- **模型优化**:`torch.nn.utils.prune` **剪枝**(非结构化=单参数、结构化=整组/整卷积核;`global_unstructured`、`L1Unstructured` 等);`torch.quantization.quantize_dynamic` **动态量化**(激活范围随计算变化,动态定缩放系数,转低位宽整型)。P124–131

## 八、模型训练实现(P133–P163)
- **流程**:加载数据集 → 定义损失 → 梯度计算与优化 → 保存模型。P133
- **数据加载**:`Dataset`(自定义需继承,复写 `__getitem__`/`__len__`)→ `DataLoader`(按批返回,`batch_size/shuffle/num_workers`);`torchvision.datasets` 提供内建数据集(MNIST/CIFAR/ImageNet 等)。P134–138
- **损失函数**:可自定义(继承 nn.Module 写 forward)或用内建 `nn.L1Loss/MSELoss/CrossEntropyLoss/NLLLoss/BCELoss`。P140–141
- ⭐**计算图与反向传播**:前向时保存中间结果便于反向链式求导;**计算图一次 backward 后立即销毁**,下次需重建 → **只推理时可不建图省内存**。`torch.no_grad()` 上下文/装饰器禁用建图(仍能前向、不算梯度)。`tensor.backward()` 求梯度。P142–146
- **叶节点**:①requires_grad=False 的张量;②用户直接创建且 requires_grad=True 的张量。`is_leaf` 查看;**反向时只有叶节点的 `.grad` 被保存**(非叶要保留需 `retain_grad`)。`detach()` 从计算图剥离成新叶张量(共享内存、requires_grad=False)。P147–149
- **自定义梯度**:用 `torch.autograd.Function`(写 `forward`/`backward`,ctx 存反向所需张量);用 `gradcheck()`(数值求导对比)、`detect_anomaly()` 验证。P150–152
- **优化器 `torch.optim`**:Adadelta/Adagrad/Adam/RMSprop/SGD/LBFGS。**训练循环**:`zero_grad()` → 前向 → 算 loss → `loss.backward()` → `optimizer.step()`。`zero_grad` 防梯度累加。P153–155
- **state_dict**:Module 的 state_dict 含含可学习参数层的 weight/bias(键如 `features.0.weight`);Optimizer 的 state_dict 含状态+待优化参数+超参数。P156–158
- **保存与恢复**:官方推荐只存 `state_dict`(.pt/.pth),`load_state_dict()` 恢复(推理前 `model.eval()`);或存检查点(.tar,含 model/optimizer state_dict、epoch、loss)用 `torch.load` 恢复继续训练。注意存 state_dict 应 deepcopy,直接赋值仅得引用会随训练变化。P159–163

## 九、驱动范例:非实时风格迁移(P165–P182)
- **思路**:给内容图 p、风格图 a,优化随机噪声图 x,使其**保留 p 的内容、又有 a 的风格**;用 ImageNet 上训好的 **VGG19**(去掉全连接+softmax)提特征。P165
- **内容损失**:取 conv4 单层,算内容图与生成图特征的**欧式距离**;`ContentLoss` 中 `target.detach()`(特征是状态值,需从图剥离)。P166, P173
- **风格损失**:取 conv1~conv5 五层,用 **Gram 矩阵(特征图内积)**表示风格,各层权重 0.2。P167, P174
- **关键实现**:`Normalization` 预处理层作为网络首层;遍历 cnn 子层在指定卷积层后插入 ContentLoss/StyleLoss 模块;**优化对象是输入图像** `input_img.requires_grad_(True)`、`model.requires_grad_(False)`;优化器 `LBFGS([input_img])`;循环里 `clamp_(0,1)`、`zero_grad`、前向累加 style/content loss、`backward`、`step(closure)`。P175–182
