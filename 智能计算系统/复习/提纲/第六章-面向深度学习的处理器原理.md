# 第六章 面向深度学习的处理器原理 · 复习提纲

> **老师强调**:第六、七章合并讲 DLP,本章是核心铺垫。重点掌握——为什么通用处理器跑深度学习"运算只占 1%"、向量/矩阵运算单元的演进、I/O 复杂度理论、DLP 三大设计(计算/存储/控制)、多核与分形扩展。⭐ 两处必考:**矩阵运算单元**(DLP 最重要的一项);**传统矩阵运算方式的问题——连线距离远、扇出(散数)多**,据此理解为何要用新电路结构(如脉动阵列/Systolic Array)。

## 一、智能任务的处理器选择(P3–P4)
- **处理智能任务的处理器**:可用 CPU、GPU、FPGA,也可用专用**深度学习处理器(DLP)**。P3
- **为何选通用处理器**:三大优势——**普及**(每台设备都有 CPU)、**廉价**(0 成本获得完备算力)、**灵活**(可与任何任务共享硬件);适合小模型、少数据、延迟/成本敏感的推理。P4

## 二、算法到执行 & "运算只占 1%"(P5–P9, P24)
- **执行链路**:算子 → 程序(C 循环)→ 指令(汇编)→ 执行(机器码)。卷积的六重循环就是典型算子。P5–P8
- ⭐**真实处理器:用于运算的芯片面积不到 1%**!绝大部分面积花在控制、缓存、寻址上。P9
- **运算只占 1% 的根因**:以**标量**为基本运算粒度 → 需大量指令;任意指令间潜在依赖,控制复杂;"内存墙"导致缓存越来越大、层次越来越多。P24

## 三、通用处理器结构回顾(P10–P23)
- **冯·诺依曼结构**:控制器+运算器+存储器+I/O,核心是"**存储程序**"(指令从主存取出)。P10–11
- **高速缓存(Cache)**:弥补主存与运算器之间的"剪刀差",自动暂存最近读取数据,通常用 **SRAM** 实现。P12–13
- **哈佛结构**:指令缓存与数据缓存分离,可同时取指与访存,互不干扰。P14
- **RISC**:通过专用 **load/store** 指令访存;实际中复杂指令先译为 RISC 微码。P15
- **分支指令**:由运算器算出下条指令地址,**计算完成前暂停取指**。P16
- 以下为提升性能的微架构手段(了解名词即可):
  - **多发射**:多条无关指令同时发射,利用多个运算器。P17
  - **地址生成单元**:专门算访存地址,支持多种寻址模式。P18
  - **寄存器重命名**:逻辑寄存器与物理寄存器分离,消除伪相关。P19
  - **乱序执行、有序提交**:实现精确例外,可撤销已执行指令。P20
  - **写入/写出队列**:暂存已执行未提交的访存指令,可撤销。P21
  - **数据前递**:上条结果直送下条运算单元,省去反复读写寄存器。P22
  - **分支预测**:未定跳转方向时按猜测投机执行;对了省等待、错了撤销。P23

## 四、软件优化的局限:控制、寻址(P25–P28)
- ◆**控制+寻址开销超过实际计算**!汇编里 control/addressing 指令远多于 calculate。P25
- **降控制开销**:循环展开(Loop unrolling);**降寻址开销**:强度削减(Strength reduction)。均为通用技巧,现代编译器已尽力,**没有非常有效的方法**。P26
- **为什么改不了**:通用处理器为通用性而设计,深度学习只是其一种应用;且即便程序规整,**每访问一个数据都必须算地址、控制循环条件**。P27–28

## 五、访存问题与软件优化(P29–P34)
- ◆**缓存四类失效行为**(会判断):
  - **容量失效**:循环访问超过缓存容量,LRU 失效。P29
  - **访问放大**:逐字不命中时缓存以"行"为单位替换,搬入大量无用数据。P29
  - **临界步幅**:条带状访问使组相联缓存提前遭遇容量失效(同一组反复冲突)。P30
  - **伪共享**:两核交替修改同一缓存行,反复使对方本地缓存无效。P31
- **缓存的复杂行为给优化带来挑战!**
- ◆**分块(tiling)**:把运算拆成固定尺寸区块处理(如 3×3),避免上述缓存问题,命中率显著提升;代价是程序更复杂(矩乘从三重循环变六重)。P32
- **递归(分治)vs 迭代(三重循环)矩乘**:谁更高效**没有定论,需测试**。递归=隐式分块、缓存友好、可用 Strassen 等快速算法;迭代=程序简单、控制寻址开销低。P33–34

## 六、从架构改善:并行操作多个数据(P35–P38)
- **通用处理器讨论**:优势=普及/廉价/灵活;缺陷=控制寻址开销高、访存优化策略复杂,**仅靠软件难改善**。P35
- **改善思路链**:观察→深度学习数据以**向量、矩阵**为主且数量多 → 思路:**一条指令并行操作多个数据** → 预期效果:**摊薄控制和寻址开销**。P36–38

## 七、向量处理器(P39–P53)
- **Flynn 分类法(1972)**:SISD / MISD / **SIMD(单指令多数据)** / MIMD。向量处理器属 SIMD。P39–40
- ◆**向量指令**:一条指令并行操作多个数据,例 `vadd v0, y, N`;把 N 遍标量循环压成几条向量指令,**摊薄控制/寻址开销**(AXPY:`y=a·x+y`)。P41–42
- **向量指令三种风格**(易考):
  - **STAR**(CDC STAR-100,1970):任意向量长度、**直接从主存读数据**。P43
  - **SWAR**(Cray-1,1975):**固定向量长度、用向量寄存器**;结果 Cray 战胜 CDC。P43
  - **SIMT**(NVIDIA Tesla,2006):靠**分歧执行(diverge)**用一条指令流实现多控制流,多线程束轮转隐藏延迟。P44
- ◆**向量处理器结构**(会画/会说):以通用处理器为基础 → 可保留标量部分(控制/寻址/少量标量运算),也可全向量;独立设计更宽的寄存器/运算/数据通路;可借用标量地址生成单元;可加向量/标量数据交换通路。P45–49
- **GPU**:典型向量(SIMD)结构。历史源于冷战核武模拟(ILLIAC IV 1966、Cray-1 1975、地球模拟器 2002)。应用:CPU 的 SSE/AVX/NEON,GPU 的 CUDA/CU。P50–52
- **向量处理器讨论**:优势=运算密度增、控制寻址摊薄、对并行应用灵活;缺陷=运算增多使**访存瓶颈更严峻**。P53

## 八、访存与 I/O 复杂度理论(P54–P62)
- **访存非常关键**(Sze et al., ISCA 2017)。P54
- ◆**执行时间双下界**:`执行时间 ≥ I/O 数据量 ÷ 最大访存带宽`,同时 `≥ 计算量 ÷ 峰值算力`;两者取大。P55
- **I/O 数据量**:至少含最初输入+最终输出。P56–57
- ⭐◆**向量化不改善访存**:标量乘 1 运算 / 3 个 I/O(2 入 1 出);向量乘 n 运算 / 3n 个 I/O——**平均每运算仍是 3**;故向量处理器须**等比例增加运算与带宽**。P58–59
- ◆**I/O 复杂度理论(Hong & Kung,1981)**:刻画运算量与 I/O 量的关系。关键结论(必记):
  - 标量:运算=1,I/O=3。
  - 向量:运算=n,I/O=3n。
  - 矩阵乘向量:运算≈n²,I/O≈n²。
  - **矩阵乘矩阵:运算≈n³,I/O≈n²** → 运算/IO 比随规模上升,**数据局部性最好**!P60
- **BLAS 三代演进**:一代向量操作(内积/AXPY)→ 二代向量-矩阵(矩阵乘向量,开销降)→ 三代矩阵运算(矩阵乘,性能潜力大)→ 今天:卷积等 DNN 基本运算,**数据局部性更优**(运算量/IO 量比高)。P61–62

## 九、深度学习处理器(DLP):矩阵运算单元(P63–P66)
- ⭐**核心思想**:基本运算单元从**向量运算扩展到矩阵运算**——矩阵运算单元是 DLP 最重要的一项。P63–64
- ◆**三种处理器对比(会画/会算运算单元数与数据通路)**:
  - 标量通用处理器:运算单元 **1**,数据通路 **2**。
  - 向量处理器:运算单元 **n**,数据通路 **2n**。
  - **DLP(矩阵):运算单元 n²,数据通路 3n**。P65
- ⭐**结论**:DLP **在相同带宽下提供更高运算能力**(运算单元 n² 增长,而数据通路仅 3n 线性增长)。这正是利用了矩阵乘"运算 n³ / IO n²"的好局部性。P66
- ⭐**传统矩阵运算电路的问题**(老师点名):简单堆 n² 个运算单元,**连线距离远、扇出(散数)多** → 时序/功耗恶化 → 需要新电路结构(如**脉动阵列 / Systolic Array**),让数据在阵列中逐拍流动,缩短连线、降低扇出。(结合 P65–66 与第七章理解。)

## 十、DLP 三大结构设计:访存 / 控制 / 计算(P67–P74)
- **访存——缓存 vs 便笺(scratchpad)**:便笺相比缓存,面积 +50%、速度 +23%、功耗 +2% 的优势,代价是**需软件控制**(缓存对程序透明)。深度学习**访存行为规律**,更适合**便笺存储**。P67
- **控制——计数循环为主**:DL 程序控制流以计数循环(for)为主 → 可专门设计**计数跳转指令**,大多数跳转**无需分支预测**。P68–69
- ◆**DLP 结构搭建步骤(会画)**:
  1. 以**精简的通用处理器**为基础,**省去分支预测器**。P70
  2. **取消数据缓存**,I/O 直连外部主存。P71
  3. 加**便笺存储器 + DMA**(代理主存与便笺间大块连续数据搬运)。P72
  4. 加**矩阵运算单元**。P73
  5. 加**矩阵指令的控制单元**(矩阵指令在提交队列与标量/访存指令同步)。P74

## 十一、神经网络芯片发展历史(P75–P80)
- **第一次热潮(1950s–60s)**:1951 Minsky 的 SNARC;1960 Rosenblatt 的 Mark-I。P75
- **第二次热潮(1980s–90s 初)**:Intel ETANN(1989,模拟电路)、CNAPS(1990,数字)、MANTRA-I(1993)、预言神(1997);特点**结构简单、规模小**。P76–78
- **第三次热潮(2006–至今)**(重要里程碑):
  - **DianNao**(中科院计算所&INRIA,2013):国际首个 DLP 架构。
  - **DaDianNao**:国际首个多核 DLP 架构。
  - 国际首个 DLP 芯片;首个深度学习指令集(奠定**寒武纪**生态)。
  - Google **TPU** 第一代;NVIDIA **Pascal**(首个面向 DL 的 GPU 架构)、V100 加入 DL 加速器;寒武纪 MLU100/MLU270。
  - 背景事件:Google Brain 猫脸识别(2012,1.6 万 CPU 核)、AlphaGo 战胜李世石(1202 CPU+176 GPU)。P79
- **三个样例**:DianNao(2013)、TPU(Google,2016)、Volta GPU(NVIDIA,2017)。P80

## 十二、DLP 规模扩展与利用率(P81–P86)
- **DLP 讨论**:优势=一条指令完成复杂线性运算(控制开销低)、同等访存达到更强算力;缺陷见下。P81
- **如何堆更强算力**:简单放大单个矩阵运算单元 → "大号""超大号" DLP。P82–84
- ⭐**利用率问题**:**简单放大矩阵运算单元会导致利用率低下**(实际算子尺寸难占满超大阵列)。P85
- ◆**TPU 的教训**:TPUv1(2016)256×256 → TPUv2(2017)128×128 → TPUv3(2018)128×128+128×128,**阵列变小但拆分变多**,提升利用率。P86

## 十三、多核 DLP 结构(P87–P101)
- **多核动机**:相比单个巨大矩阵单元,**多个较小矩阵单元更灵活**;代价是硬件成本(尤其带宽)增加——**按需设计**。P87
- ◆**多核搭建(会画)**:复制核心 → 问题:**主存接口要求翻倍** → 用**总线**共享主存通路,争用时**仲裁**决定通行权。P88–91
- **UMA 模型**:把一份完整 DLP 视为一个核,多核挂同一数据总线访问主存——"**一字长蛇阵**"(一致内存访问)。P92–93
- ◆**长蛇阵能无限长吗?不能——总线争用成为瓶颈**。P94–95
- **层级扩展**:以 UMA 多核为基础,逐步添加**局部存储器 → 局部控制器/运算器 → 局部 DMA(连外部存储)**;再把整个 UMA 多核视为一个"核",向上递归。P96–101

## 十四、大规模 DLP:分形与总结(P102–P104)
- ⭐**分形 DLP**:以相同规则任意扩展的 DLP 结构;**同一份分治程序运行在所有局部控制器上**;无论规模多大,**使用者视角一致**。P102
- **真实 DLP**:用于运算的芯片面积**达到 30%**(对比通用处理器 <1%),控制/数据访问/便笺占其余。P103
- **总结——DLP 特点**(易考四点):
  - **计算**:矩阵、卷积为主,辅以标量、向量。
  - **控制**:计数循环为主,辅以条件分支。
  - **存储**:便笺存储器为主,辅以寄存器。
  - **扩展**:采用**分形**方式。
  - **基本原理**:**改善基本运算的 I/O 复杂度**。P104
