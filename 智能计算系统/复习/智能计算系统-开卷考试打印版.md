## 1. 答题模板

### 1.1 “比较类”简答模板

先定义两者，再从 3 个维度比较，最后说适用场景。

示例：静态图 vs 动态图。

```text
静态图：先构建完整计算图，再执行。优点是可全局优化、执行效率高；缺点是调试不方便、灵活性差。
动态图：边执行边构建计算图。优点是灵活、易调试、立即得到结果；缺点是全局优化空间较小。
典型：TensorFlow 1.x 偏静态图，PyTorch 偏动态图；现代框架通常两者都支持。
```

### 1.2 “为什么”分析模板

按“问题背景 -> 原因 -> 解决方法 -> 代价/适用”写。

示例：为什么需要 ZeRO。

```text
背景：大模型参数、梯度、优化器状态很大，数据并行时每张 GPU 都存一份，产生冗余。
原因：AdamW 优化器状态尤其占显存，单卡显存不足。
方法：ZeRO 将优化器状态、梯度、参数分片到不同 GPU，用时通过通信重建。
代价：通信变多，但显存压力大幅降低；可进一步 Offload 到 CPU/NVMe。
```

### 1.3 “流程类”答题模板

写清输入、核心步骤、输出。

示例：扩散模型。

```text
输入：真实样本 x0。
正向扩散：逐步加入高斯噪声，把数据分布变为近似标准正态。
训练：随机取时间步 t 和噪声，训练噪声预测网络预测该步噪声。
反向去噪：从随机噪声 xT 开始，逐步去噪生成样本。
输出：接近真实数据分布的新样本。
```

### 1.4 “给例子分类”模板

先看关键词。

```text
图级优化：常量折叠、公共子表达式消除、代数化简、布局优化、算子融合、子图替换。
算子级优化：循环分块 tiling、向量化 vectorize、并行化 parallel、展开 unroll、SIMD、自动调优。
```

## 2. 第二章：深度学习基础

### 2.1 参数量

全连接层：

```text
参数量 = 输入数 * 输出数 + 输出数
```

卷积层见 3.1。

可能考法：

- 给 MLP 层数和神经元个数，算总参数。
- 填空：每层参数量除了权重还要加“偏置”。

### 2.2 梯度下降与反向传播

梯度下降：

```text
w <- w - η * ∂L/∂w
```

反向传播链式法则：

```text
∂L/∂w = ∂L/∂ŷ * ∂ŷ/∂z * ∂z/∂w
```

sigmoid 导数：

```text
σ'(z)=σ(z)(1-σ(z))
```

可能考法：

- 给简单网络数值，做一次正向和反向更新。
- 问为什么梯度下降能找参数：负梯度方向是损失下降最快方向。
- 问 mini-batch SGD：在全量 GD 与单样本 SGD 之间折中，兼顾效率和稳定性。

### 2.3 激活函数

| 函数 | 关键特点 | 优点 | 缺点/场景 |
|---|---|---|---|
| sigmoid | 输出 0 到 1 | 可表示概率 | 非 0 均值、指数慢、饱和导致梯度消失 |
| tanh | 输出 -1 到 1 | 0 均值 | 饱和区梯度消失 |
| ReLU | `max(0,x)` | 正区梯度不衰减、计算快 | 负区恒 0，可能死亡 ReLU |
| Leaky/PReLU | 负区有小斜率 | 缓解 ReLU 死亡 | PReLU 斜率可训练 |
| ELU | 负区指数平滑 | 均值近 0、收敛较快 | 指数开销 |
| GELU | 概率门控式平滑激活 | BERT/GPT/T5 常用 | 比 ReLU 复杂 |
| SiLU/Swish | `x*sigmoid(x)` | 平滑、泛化好 | LLaMA/DeepSeek 常见变体 SwiGLU |

可能考法：

- 选择：哪种激活有死亡问题？ReLU。
- 简答：为什么 GELU/SiLU 在大模型中常见？平滑、优化更稳定、表达能力好。
- 简答：为什么激活函数需要非线性？否则多层线性仍等价于一层线性。

### 2.4 损失函数

MSE：

```text
L = 1/2 (y - ŷ)^2
```

交叉熵：

```text
L = -[y ln ŷ + (1-y) ln(1-ŷ)]
```

MSE + sigmoid 的问题：梯度含 `σ'(z)`，饱和区梯度小，更新慢。  
交叉熵 + sigmoid：反向时可抵消 sigmoid 导数项，分类训练更快更稳。

可能考法：

- 问均方差和交叉熵区别。
- 问交叉熵为何解决更新慢。
- 填空：损失函数是参数的函数、标量、可微。

### 2.5 欠拟合/过拟合/泛化

| 概念 | 现象 | 处理 |
|---|---|---|
| 欠拟合 | 训练集误差也大 | 增加模型复杂度、训练更充分、换特征 |
| 过拟合 | 训练好，测试差 | 增加数据、简化模型、正则化等 |
| 泛化 | 对新场景适应能力 | 测试集/新场景精度高说明泛化强 |

防过拟合必须会列：

1. 参数范数惩罚：L1/L2。
2. 稀疏化。
3. Bagging。
4. Dropout。
5. 提前终止。
6. 数据增广。

根本思路：数据更多样，模型更简单。

### 2.6 交叉验证

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 留一验证 | n 个样本每次留 1 个测试 | 数据利用充分 | 训练 n 次，计算贵 |
| K 折交叉验证 | 分 K 份，轮流 1 份测试 | 成本比留一低 | 仍需训练 K 次 |

留一是 `K=n` 的特例。小数据集更常用，大规模深度学习通常直接训练/验证/测试划分。

## 3. 第三章：深度学习应用

### 3.1 CNN 与卷积计算

CNN 减参靠：局部连接 + 权重共享。

卷积与数学卷积区别：数学卷积翻转卷积核；神经网络卷积通常不翻转，本质是相关/内积。

输出尺寸：

```text
W_o = floor((W_i + 2p_w - K_w)/s_w) + 1
H_o = floor((H_i + 2p_h - K_h)/s_h) + 1
```

卷积层参数量：

```text
参数量 = C_o * K_h * K_w * C_i + C_o
```

卷积计算量：

```text
计算量 = W_o * H_o * C_o * C_i * K_h * K_w
```

padding：边界扩充，控制输出尺寸，保留边缘信息。  
stride：滑动步长，步长越大输出越小。  
池化：缩小特征图、减少计算、缓解过拟合，不引入参数。

可能考法：

- 给 `5x5` 输入、`3x3` 核、`p=1`、`s=2`，算输出。
- 给 `1x3` 或 `3x1` 核，宽高分别代公式。
- 问 CNN 为什么比全连接适合图像。
- 给任务要求，画大致网络：`Input -> Conv/ReLU/Pool -> FC/Softmax`；检测任务加分类头和 bbox 回归头。

### 3.2 图像分类网络脉络

| 网络 | 解决什么问题 | 关键词 |
|---|---|---|
| AlexNet | 深 CNN 能否做大规模图像分类 | ReLU、Dropout、MaxPool、数据增强 |
| VGG | 能否更深、更规整 | 堆叠 `3x3` 小卷积 |
| Inception | 不暴涨计算量下变宽变深 | 多分支、`1x1` 瓶颈降维 |
| ResNet | 深层网络退化 | 残差连接、shortcut |
| DenseNet | 特征/梯度复用 | 层间密集连接 |
| SENet | 通道重要性 | Squeeze + Excitation |

高频点：

- VGG 多个小卷积替代大卷积：参数少、非线性多、表达强。
- Inception `1x1` 卷积：跨通道组合，降维减参。
- ResNet 退化问题不是过拟合；是深层训练误差变高。残差学习 `F(x)=H(x)-x` 更易优化。

### 3.3 检测指标

IoU：

```text
IoU = 交集面积 / 并集面积
```

Precision/Recall：

```text
Precision = TP/(TP+FP)
Recall = TP/(TP+FN)
```

常见现象：阈值降低，检测框更多，Recall 上升，Precision 可能下降。

mAP：多类别 AP 的平均。AP 由 Precision-Recall 曲线/不同 recall 上 precision 综合得到。

可能考法：

- 给两个框坐标，算 IoU。
- 给 TP/FP/FN，算 precision 和 recall。
- 问检测为什么不能只看 accuracy：还要评价定位框质量和召回。

### 3.4 目标检测算法脉络

| 算法 | 思路 | 解决/问题 |
|---|---|---|
| R-CNN | Selective Search 候选框 + 每框 CNN + SVM | 准但慢，重复计算多 |
| Fast R-CNN | 整图卷积 + ROI Pooling | 复用特征，瓶颈仍是候选框 |
| Faster R-CNN | RPN 生成候选框 | 候选框生成也网络化 |
| YOLO | 一阶段直接回归框和类别 | 快，适合实时 |
| SSD | 多尺度特征图 + default boxes | 兼顾速度和多尺度检测 |

必会区分：两阶段先候选框再分类/回归；一阶段直接输出框和类别。

### 3.5 序列学习

token：文本基本单位，可为字符、词、subword；大模型按 token 计费。  
BPE：不断合并最频繁出现的一对 token。  
embedding：离散 token 到连续向量；one-hot 稀疏且不能表达相似性，embedding 稠密且表达语义。

RNN：

```text
h(t)=f(W h(t-1)+U x(t)+b)
```

RNN 特点：sequence、recurrent、memory、参数共享。  
问题：BPTT 长链相乘导致梯度消失/爆炸，难学长期依赖。  
处理：梯度爆炸用梯度截断；梯度消失用 LSTM/GRU。

LSTM：单元状态 + 遗忘门、输入门、输出门。  
GRU：更新门、重置门；参数少、训练快。  
Seq2Seq：Encoder 编码输入，Decoder 生成输出，适合输入输出不等长。缺点是固定长度语义向量存不下长序列，且无法区分重要性。

### 3.6 注意力与 Transformer

缩放点积注意力：

```text
Attention(Q,K,V)=softmax(QK^T/sqrt(d_k)+Mask)V
```

为什么除以 `sqrt(d_k)`：Q/K 内积方差随维度增大而增大，softmax 容易饱和；缩放后梯度更稳定。

自注意力：Q/K/V 来自同一输入，捕捉序列内部关系。  
多头注意力：多组投影并行学习不同关系，再拼接。

Transformer Encoder：

```text
Multi-Head Self-Attention -> Add&Norm -> FFN -> Add&Norm
```

Transformer Decoder：

```text
Masked Self-Attention -> Cross-Attention -> FFN
```

mask：防止看到未来 token，满足自回归。  
cross-attention：Q 来自 decoder，K/V 来自 encoder。  
位置编码：自注意力本身无顺序信息，需注入位置信息。

### 3.7 BERT/GPT/Decoder-only

| 架构 | 代表 | 特点 | 任务 |
|---|---|---|---|
| Encoder-Decoder | Transformer、T5、GLM | 编码输入、解码输出 | 翻译、摘要 |
| Encoder-only | BERT | 双向理解，无 mask | 分类、检索、理解 |
| Decoder-only | GPT、LLaMA、DeepSeek | 自回归生成，causal mask | 生成、对话、推理 |

Decoder-only 成主流原因：

1. 自回归生成天然适合语言建模。
2. in-context learning 强，prompt 直接作用于 decoder 每层。
3. causal attention 下三角结构建模能力强。
4. 推理可复用 KV cache。
5. FlashAttention、Megatron 等系统优化成熟。
6. zero-shot/few-shot 泛化效果好。

### 3.8 图像 Transformer

DETR：把目标检测看作集合预测，减少 anchor/NMS 等手工模块。  
ViT：图像切 patch，patch 当 token，加 class token 和位置编码，输入 Transformer Encoder。  
Swin：窗口内自注意力 + shifted window，降低计算并加强窗口间联系。

可能考法：

- 问 ViT 为什么不用像素当 token：序列太长，计算量太大。
- 问 Swin 与 ViT 区别：Swin 分层、局部窗口注意力、移动窗口。

### 3.9 生成模型

GAN：生成器 G 造假样本，判别器 D 分真假，二者极小极大博弈。问题：梯度消失、模式崩溃。  
CGAN：加入类别/文本等条件，使生成可控。  
VAE：编码器输出概率分布参数，从分布采样后解码；损失=重构项+KL 散度；重参数化 `z=μ+σε`。  
Diffusion：正向扩散逐步加噪；反向去噪逐步生成；训练噪声预测器。  
Stable Diffusion：在隐空间扩散，显著降低显存和计算。

可能考法：

- 问扩散模型两个过程。
- 问 Stable Diffusion 为什么是效率里程碑。
- 问 GAN 和 VAE 区别：GAN 对抗学习，VAE 学隐变量分布。

### 3.10 多模态

CLIP：图像编码器 + 文本编码器，用图文对比学习，让匹配图文 embedding 接近，不匹配远离。推理时把类别写成文本，做 zero-shot 分类。  
BLIP：统一图文理解与生成，含 ITC/ITM/LM 损失。  
BLIP-2：冻结视觉编码器和 LLM，只训练 Q-Former。  
VLA：Vision-Language-Action，视觉感知 + 语言指令 + 动作输出，常用于机器人/具身智能。

可能考法：

- 问 CLIP 为什么有 zero-shot 能力：类别可转文本，与图像 embedding 匹配。
- 问 VLA 与 VLM 区别：VLA 要输出动作并与环境交互。

### 3.11 智能体

大模型智能体三部件：

1. Planning：任务分解、反思，CoT/ToT/ReAct。
2. Memory：短期上下文、长期向量库/RAG。
3. Tool Use：函数调用、API、插件、外部模型。

可能考法：

- 填空：智能体三部件。
- 简答：记忆、规划、工具分别干什么。

### 3.12 量化

量化：把 FP32/BF16 等高位宽表示换成 INT8/FP8/FP4 等低位宽，降低存储、计算、能耗。

分类：

| 维度 | 类型 |
|---|---|
| 对称性 | 对称量化、非对称量化 |
| 均匀性 | 均匀量化、非均匀量化 |
| 粒度 | 分层、分通道、分 token、分组/分块 |

PTQ vs QAT：

| 方法 | 流程 | 优点 | 缺点 |
|---|---|---|---|
| PTQ | 预训练模型 + 校准数据 -> 量化 | 简单、成本低 | 低位宽精度差 |
| QAT | 量化后微调/再训练 | 精度更好 | 训练成本高 |

KV cache：缓存历史 token 的 K/V，新 token 只算自己的 Q/K/V 与历史交互，减少自回归推理重复计算。  
KV 量化：降低 KV cache 内存和读取带宽，适合长序列和 decode。

## 4. 第四章：编程框架使用

### 4.1 Tensor vs 普通矩阵

Tensor：计算图中的数据载体，支持 GPU/DLP、自动求导、计算图。  
NumPy ndarray：原生 CPU 数组，不支持框架自动求导。

转换：

```python
torch.from_numpy(array)
tensor.numpy()
```

注意：CPU tensor 与 NumPy 通常共享内存；GPU tensor 需 `.cpu().numpy()`。

数据布局：

- NCHW：PyTorch/GPU 常用，同通道数据连续。
- NHWC：TensorFlow/CPU 常见，同一像素不同通道连续。

可能考法：

- 问 Tensor 为什么更适合深度学习：设备支持、自动求导、多维批量/通道运算。
- 问转换共享内存风险。

### 4.2 PyTorch 基本训练流程

```python
optimizer.zero_grad()
out = model(x)
loss = criterion(out, y)
loss.backward()
optimizer.step()
```

`zero_grad()` 防止梯度累加。  
`model.train()` 启用 Dropout/BN 训练行为；`model.eval()` 关闭 Dropout，BN 用 running mean/var。

### 4.3 广播机制

规则：

1. 从末尾维开始对齐。
2. 每维必须满足：相同，或一个为 1，或一个缺失。
3. 不满足则报错。

例：

```text
(2,3,3) 和 (3,1)
(3,1) 补成 (1,3,1)
2 vs 1 可，3 vs 3 可，3 vs 1 可
结果 (2,3,3)
```

不可广播例：

```text
(2,3) 和 (2,2)：末维 3 vs 2，不同且都非 1 -> 报错
```

### 4.4 计算图、静态图、动态图

计算图：节点表示张量/参数/操作，边表示数据依赖或控制依赖。

| 类型 | 特点 | 优点 | 缺点 |
|---|---|---|---|
| 静态图 | 先定义整图再运行 | 可全局优化、速度快 | 调试不方便 |
| 动态图 | 边运行边建图 | 灵活、调试方便 | 优化不方便 |

PyTorch 传统上是动态图；TensorFlow 1.x 是静态图；现代框架多同时支持。

## 5. 第五章：编程框架原理

### 5.1 框架四大模块与设计哲学

四大模块：

1. 计算图构建。
2. 计算图执行。
3. 深度学习编译。
4. 分布式训练。

设计哲学：

- 简洁性：用户关注算法和部署策略。
- 易用性：接口直观、开发范式熟悉。
- 高效性：静态图、编译、分布式提升性能。

### 5.2 自动微分

四种求导方法：

| 方法 | 缺点 |
|---|---|
| 手动求导 | 大模型难手推，模型变公式变 |
| 数值求导 | 慢，有舍入/截断误差 |
| 符号求导 | 表达式膨胀 |
| 自动求导 | 框架实现复杂，但适合深度学习 |

自动微分两步：

1. 正向：构建计算图，保存中间值。
2. 反向：反向遍历图，链式求导；多路径梯度累加。

可能考法：

- 给简单表达式做正向/反向。
- 问自动微分为何优于数值求导。
- 问框架最大工作量是什么：自动求导。

### 5.3 计算图执行（了解）

计算图执行负责把张量和算子映射到设备上运行，包括：

- 设备管理：CPU/GPU/DLP、执行流、事件、同步。
- 张量实现：逻辑视图与物理存储。
- 算子执行：拓扑排序得到执行序列，按设备分派 kernel。

### 5.4 深度学习编译为什么重要

原因：

1. 新硬件/新算子多，手写适配维护成本高。
2. 手工算子优化难探索全图空间。
3. 编译器可做图级全局优化和算子级自动调优。
4. 自动生成目标硬件高性能代码。

### 5.5 图级优化 vs 算子级优化

| 类型 | 判断 | 例子 |
|---|---|---|
| 图级优化 | 不深入算子内部，只改计算图/数据流 | 子图替换、常量折叠、公共子表达式消除、代数化简、布局优化、算子融合 |
| 算子级优化 | 调底层 kernel/循环/访存 | tiling、vectorize、parallel、unroll、SIMD、自动调优 |

注意：算子融合通常作为图级优化出现；融合后的 kernel 如何高效执行是算子级问题。

### 5.6 分布式架构

| 架构 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| 参数服务器 | Server 存参数，Worker 算梯度 | 灵活 | 中心瓶颈、单点故障、一致性问题 |
| 集合通信 | 无中心，多节点点对点通信 | 去中心化、常用于大规模训练 | 对网络要求高 |

### 5.7 集合通信原语

| 原语 | 操作 | 常见用途 |
|---|---|---|
| Broadcast | 一到多 | 参数初始化/同步 |
| Scatter | 一到多切块 | 分发分片 |
| Gather | 多到一 | 收集结果 |
| All-Gather | 多到多收集 | 所有节点获得全部分片 |
| Reduce | 多到一归约 | 梯度汇总到主节点 |
| All-Reduce | 归约后广播给所有 | 数据并行梯度平均 |
| Reduce-Scatter | 归约后分片 | ZeRO/FSDP |
| All-to-All | 多对多交换 | 张量/序列并行重排 |

### 5.8 并行策略

| 策略 | 切分对象 | 解决 |
|---|---|---|
| 数据并行 | 数据 | 算力不足 |
| 模型并行 | 参数/层/算子 | 显存不足 |
| 张量并行 | 单算子张量 | 单层矩阵太大 |
| 流水并行 | 层/阶段 | 模型太深 |
| 序列并行 | token 序列维 | 长上下文 |
| 混合并行 | 数据+模型 | 超大模型 |

## 6. 第六章：处理器原理

### 6.1 通用处理器问题

通用处理器中真正用于运算的面积很少，大量面积用于控制、缓存、寻址。深度学习计算规整，但通用处理器仍要执行大量 load/store、地址计算、循环控制。

向量处理器用一条指令处理多个数据，摊薄控制/寻址开销，但访存瓶颈仍存在。

### 6.2 I/O 复杂度

| 运算 | 运算量 | I/O | 结论 |
|---|---|---|---|
| 标量 | 1 | 3 | 局部性差 |
| 向量 | n | 3n | 单位运算 I/O 未改善 |
| 矩阵乘向量 | n² | n² | 一般 |
| 矩阵乘矩阵 | n³ | n² | 局部性最好 |

结论：矩阵乘的计算/I-O 比随规模增大而提高，适合 DLP 重点加速。

### 6.3 DLP 矩阵运算单元

| 处理器 | 运算单元 | 数据通路 |
|---|---|---|
| 标量 | 1 | 2 |
| 向量 | n | 2n |
| DLP 矩阵 | n² | 3n |

结论：DLP 在相同带宽下可提供更高算力。

传统矩阵电路问题：连线距离远、扇出多、功耗和时序差。解决：脉动阵列，让数据在相邻 PE 间逐拍流动。

### 6.4 DLP 三大设计

1. 计算：矩阵运算为主，辅以向量/标量。
2. 存储：便笺存储器 scratchpad + DMA。
3. 控制：计数循环为主，简化分支预测等复杂控制。

---

## 7. 第七章：处理器架构

### 7.1 DLP 两大结构特点

必背：

1. 取消传统输入，直接用 IO 连接外部。
2. 增设便笺存储器从机，通过 DMA 直接访问外部 DRAM。

优势：一条 load 装整块数据，一条指令完成矩阵计算，一条 store 写回，减少通用处理器大量控制/寻址/访存开销。

### 7.2 矩阵单元和脉动阵列

矩阵单元组合：乘法器 -> 内积单元 -> 矩阵乘向量 -> 矩阵乘矩阵。  
优化：权值近端存储、激活广播、多内积单元并行、多组件嵌套。

脉动阵列优势：局部短连接、扇出少、计算-I/O 比更好。  
脉动阵列困难：启动/排空延迟高，专用性强。

### 7.3 便笺、DMA、软件流水线

便笺存储器是 DLP 核内数据枢纽。  
DMA 负责主存和便笺之间大块数据搬运。  
软件流水线让 load/compute/store 交叠执行，用显式 sync 同步，减少硬件复杂度。

## 8. 第九章：大模型计算系统

### 8.1 大模型发展与系统需求

大模型训练计算量约随参数规模和数据规模增长。模型需求增长远快于芯片算力增长，因此需要算法、系统软件、硬件协同优化。

BLOOM 例子：数据并行 x 张量并行 x 流水线并行。  
训练存储包含：模型权重、梯度、优化器状态、激活值。

### 8.2 三类优化

必须会答：

1. 计算优化。
2. 存储优化。
3. 稳定性优化。

### 8.3 计算优化

训练：稀疏注意力、TF32/BF16/FP16 混合精度。  
推理：连续批处理、KV cache。

### 8.4 存储优化

ZeRO 零冗余优化器：

- 问题：数据并行每卡重复存参数、梯度、优化器状态。
- 方法：把优化器状态/梯度/参数分片到各 GPU，用时通信重建。
- 扩展：ZeRO-Offload 到 CPU，ZeRO-Infinity 到 NVMe。

重计算：正向只存检查点，反向重算中间激活；用计算换存储。  
FlashAttention：分块+融合，中间 `S=QK^T`、`P=softmax(S)` 不写回显存，减少片外访存。  
KV cache 分页：减少 KV cache 动态分配碎片。

### 8.5 稳定性优化

大模型训练时间长、节点多，故障频繁。重点手段：

1. Checkpoint：定期保存训练状态，故障后回滚。
2. Elastic training：资源变化或节点故障时弹性恢复。
3. Redundant computations：冗余计算提高容错。

答题句：大规模训练中故障是常态，稳定性优化的目标是减少故障造成的时间和资源浪费。

## 10. 程序设计题 PyTorch 常用代码

> 开卷考试程序题一般不会要求写复杂工程，重点是结构完整、API 用对、训练流程正确。

### 10.1 最小 CNN 分类网络

适用题目：写一个图像分类 CNN，输入 `3x32x32`，输出 10 类。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SmallCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 16, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(16, 32, kernel_size=3, padding=1)
        self.pool = nn.MaxPool2d(kernel_size=2, stride=2)
        self.fc = nn.Linear(32 * 8 * 8, num_classes)

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))  # [N,3,32,32] -> [N,16,16,16]
        x = self.pool(F.relu(self.conv2(x)))  # [N,16,16,16] -> [N,32,8,8]
        x = torch.flatten(x, 1)
        x = self.fc(x)
        return x
```

得分点：

- 继承 `nn.Module`。
- `__init__` 定义层，`forward` 定义前向。
- `Conv2d` 输入输出通道写对。
- `flatten(x, 1)` 保留 batch 维。
- 分类最后输出 logits，不需要手动 softmax，`CrossEntropyLoss` 内部会处理。

### 10.2 一次完整训练迭代

```python
model = SmallCNN(num_classes=10)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

images = torch.randn(16, 3, 32, 32)
labels = torch.randint(0, 10, (16,))

model.train()
optimizer.zero_grad()
logits = model(images)
loss = criterion(logits, labels)
loss.backward()
optimizer.step()
```

顺序必须记住：

```text
zero_grad -> forward -> loss -> backward -> step
```

常见扣分：

- 忘记 `zero_grad()`，导致梯度累加。
- `loss.backward()` 和 `optimizer.step()` 顺序写反。
- 用 `CrossEntropyLoss` 前手动 softmax，通常没必要。

### 10.3 推理代码

```python
model.eval()
with torch.no_grad():
    logits = model(images)
    pred = logits.argmax(dim=1)
```

解释：

- `eval()`：关闭 Dropout，BN 使用 running mean/var。
- `no_grad()`：不构建计算图，省内存省时间。
- `argmax(dim=1)`：取类别维最大值作为预测类别。

### 10.4 Dataset / DataLoader 模板

适用题目：要求自定义数据集并按 batch 训练。

```python
from torch.utils.data import Dataset, DataLoader

class MyDataset(Dataset):
    def __init__(self, xs, ys):
        self.xs = xs
        self.ys = ys

    def __len__(self):
        return len(self.xs)

    def __getitem__(self, idx):
        return self.xs[idx], self.ys[idx]

xs = torch.randn(100, 3, 32, 32)
ys = torch.randint(0, 10, (100,))
loader = DataLoader(MyDataset(xs, ys), batch_size=16, shuffle=True)

for images, labels in loader:
    optimizer.zero_grad()
    logits = model(images)
    loss = criterion(logits, labels)
    loss.backward()
    optimizer.step()
```

得分点：

- 自定义 `Dataset` 必须实现 `__len__` 和 `__getitem__`。
- `DataLoader` 负责 batch、shuffle、并行加载。

### 10.5 `nn.Module` vs `nn.functional`

两种写法都常见。

```python
class NetA(nn.Module):
    def __init__(self):
        super().__init__()
        self.relu = nn.ReLU()

    def forward(self, x):
        return self.relu(x)

class NetB(nn.Module):
    def forward(self, x):
        return F.relu(x)
```

区别：

- `nn.xxx` 是模块类，可有状态/参数，通常在 `__init__` 里定义。
- `F.xxx` 是函数，通常在 `forward` 里直接调用。
- `Conv2d`、`Linear` 这类有参数的层更推荐用 `nn.Module` 形式管理。

### 10.6 冻结部分参数

适用题目：迁移学习/微调。

```python
for p in model.parameters():
    p.requires_grad = False

model.fc = nn.Linear(32 * 8 * 8, 10)
optimizer = torch.optim.Adam(model.fc.parameters(), lr=1e-3)
```

解释：冻结旧参数，只训练新分类头。

### 10.8 计算卷积输出尺寸函数

适用题目：写函数计算卷积/池化输出尺寸。

```python
def _pair(x):
    if isinstance(x, tuple):
        return x
    return (x, x)

def conv2d_output_shape(h, w, kh, kw, padding=0, stride=1):
    ph, pw = _pair(padding)
    sh, sw = _pair(stride)
    out_h = (h + 2 * ph - kh) // sh + 1
    out_w = (w + 2 * pw - kw) // sw + 1
    return out_h, out_w

print(conv2d_output_shape(32, 32, 3, 3, padding=1, stride=1))  # (32, 32)
print(conv2d_output_shape(5, 5, 3, 1, padding=(1, 0), stride=2))  # (3, 3)
```

### 10.9 广播判断函数

适用题目：判断两个 shape 是否能广播，并返回结果 shape。

```python
def can_broadcast(shape_a, shape_b):
    a = list(shape_a)
    b = list(shape_b)
    n = max(len(a), len(b))
    a = [1] * (n - len(a)) + a
    b = [1] * (n - len(b)) + b

    out = []
    for x, y in zip(a, b):
        if x == y:
            out.append(x)
        elif x == 1:
            out.append(y)
        elif y == 1:
            out.append(x)
        else:
            return None
    return tuple(out)

print(can_broadcast((2, 3, 3), (3, 1)))  # (2, 3, 3)
print(can_broadcast((2, 3), (2, 2)))     # None
```

### 10.10 手写简单 MLP

适用题目：不用 CNN，写全连接分类器。

```python
class MLP(nn.Module):
    def __init__(self, in_dim=784, hidden=128, num_classes=10):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.ReLU(),
            nn.Linear(hidden, num_classes),
        )

    def forward(self, x):
        x = torch.flatten(x, 1)
        return self.net(x)
```

### 10.11 手写自定义损失

适用题目：自定义 MSE。

```python
class MyMSELoss(nn.Module):
    def forward(self, pred, target):
        return ((pred - target) ** 2).mean()
```

## 11. 易错点

- ResNet 解决的是退化问题，不是普通过拟合。
- BN 跨 batch 统计，LN 在样本内部统计。
- Dropout 训练启用，推理关闭。
- `torch.from_numpy` 与 `.numpy()` 常共享内存。
- 广播从末尾维对齐，不是从开头对齐。
- All-Reduce 是所有节点都有归约结果，Reduce 只有一个节点有。
- ZeRO 是存储优化，不是稳定性优化。
- FlashAttention 主要省片外访存，不是简单改变 attention 数学定义。
- KV cache 是推理缓存，不是训练参数。
- 图级优化处理图结构；算子级优化处理底层循环和硬件映射。
- DLP 的便笺存储器由软件控制，不同于硬件自动 Cache。
- 脉动阵列优势是局部连接和低扇出，但有启动/排空延迟。
